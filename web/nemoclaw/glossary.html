The glossary behind web_search

When an agent in this course calls its web_search tool (the one you wire by hand in Module 1c), it does not reach the open web. It searches a curated index of NVIDIA glossary terms that ships with the course and runs entirely in your browser: no API key, no proxy, no lab service. This page shows what is in that index, how it reaches you, and lets you run the exact search the agent runs.

What is delivered, and how it is cached

…
glossary terms in one file, assets/glossary_index.json (…).
Same-origin. The file ships in the same bundle as this page, so the browser loads it with no external request, no key, and no CORS.
Fetched once, then cached. _shared.js holds the parsed index in a module-level promise (_glossaryIndexP); every later search reuses it with no second fetch.
Reproducible. Regenerated from the live glossary by scripts/vendor_glossary.py --index, so the contents are auditable, not a black box.
agent calls web_search(query)→ score every term (cached index)→ return the top matches

The API the tool wraps

Two functions back the same tool contract. Both return { results: [{ title, body, href }], count, unreachable }, so the agent code never changes when the backend does:

webSearch(query) is the ranked lookup. It scores every term against the query by name, then tags, then blurb, and returns the top matches. The broad search the agent grounds answers in.
instantAnswer(query) is the narrow lookup. It returns one term's definition only when the query names it, and nothing for a free-form question. The entity-keyed counterpart.
