Docker Router

The one service that holds the host Docker socket, so the lab kernel never has to. It serves read-only diagnostics over the running stack (/health, /containers, /containers/{name}/logs) and a bounded lifecycle control: start, stop, restart, or status an on-demand service drawn from a fixed allow-list. Profiled services that have never been created are stood up through the project's own compose config, resolved from a live container's labels.

The allow-list is the security boundary. An agent that can run arbitrary docker, or that holds the raw socket, has an unbounded and unprovable blast radius on the host. Here POST /lifecycle/{service}/{action} acts on ONLY the services in LIFECYCLE_SERVICES with ONLY the four verbs in LIFECYCLE_ACTIONS. Everything off the list returns 403 before any Docker call runs. The essential services (lab, nginx, llm_client) are intentionally absent, so this path can never take the lab down. That bound is the provable-security lesson: when the reachable state space is finite and auditable, the worst case is enumerable. The same principle drives the bounded console in services/openclaw.

Agent / automation notes

The skill-meta tests array is the machine-readable contract; the rendered list is its executable form. A green run means the Docker socket is reachable, the container list answers, an allow-listed lifecycle verb succeeds, and a service off the allow-list is refused with 403.

The bound is the point. Reach it from a notebook by calling the /lifecycle route rather than the kernel ever touching the Docker socket. Full prose and the provable-security framing live in services/00_openclaw.md.
