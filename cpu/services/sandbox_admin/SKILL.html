sandbox-admin

The control plane for the OpenShell-sandboxed OpenClaw deployment (sandbox-admin:8099). It manages the sandbox policy, a cron registry, and a bounded read-only sandbox exec console. A notebook drives all three over HTTP, so a student never needs exec access to the sandbox itself.

A policy reload writes the new YAML and restarts openclaw. OpenShell sets up Landlock, seccomp, and netns at boot before the agent process is forked, so it does not re-read the policy on SIGHUP. Restart is the only way to make a policy change take effect.

The allow-list is the security boundary. The bounded console (POST /admin/sandbox/exec {argv}) accepts 12 generic read-only verbs plus the openclaw read-only subcommands. An argv[0] off the list, or an openclaw subcommand off the read-only prefix list, returns 403 before any process starts. The reachable surface is finite and enumerable by design.

Agent / automation notes

The skill-meta tests array is the machine-readable contract; the rendered list is its executable form. A green run means health answers, the policy is readable, the service inventory returns, and the bounded console enforces its allow-list (an allowed verb passes, a refused verb is 403).

Full prose lives in 00_sandbox_admin.md. The bounded console and the OpenShell policy story are driven by the released course in web/nemoclaw/04a-safety.html; the openclaw service SKILL references the same console.
