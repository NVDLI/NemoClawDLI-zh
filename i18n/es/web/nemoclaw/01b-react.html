El ciclo ReAct

Un agente basado en un modelo de lenguaje ejecuta el mismo ciclo de percibir, razonar y actuar que cualquier otro agente, con un detalle que da nombre al patrón: el modelo razona con palabras entre las acciones que realiza. Yao et al. (2022) lo denominaron ReAct, por razonamiento y acción. Los autores observaron que intercalar pasos breves de razonamiento con el uso de herramientas resuelve muchas tareas con mayor fiabilidad que planificar todo de antemano o actuar sin razonar.

Una herramienta es código que el entorno de ejecución puede ejecutar para el modelo: una función con nombre, descripción, esquema de entrada y valor de retorno. Una llamada a herramienta es la solicitud estructurada que genera el modelo. El entorno de ejecución interpreta la solicitud, ejecuta la función, añade el resultado y vuelve a llamar al modelo.

Este ciclo es la base sobre la cual la mayoría de los frameworks de agentes de propósito general se construyen, incluido createReactAgent de LangChain. El resto del módulo construye las piezas necesarias para llegar a ese agente.

El campo que decide el siguiente paso

Todas las respuestas de chat-completions llevan un campo finish_reason que informa por qué el modelo dejó de generar. Dentro de un ciclo de agente, Esta señal permite decidir qué hacer después: ejecutar una herramienta, devolver la respuesta al usuario o gestionar un error. Antes de leer lo que significan sus valores, haga dos llamadas y observe el campo cambiar.

La primera llamada respondió sola y regresó "stop" . La segunda recibió Una herramienta y una pregunta que los datos de entrenamiento no pueden responder. En lugar de parar, Cambió a "tool_calls" y entregó al código el nombre de la función que debe ejecutar. Estos dos valores cubren la rama común. El resto señala problemas que rotean el ciclo para un flujo de fallback del entorno de ejecución, en el cual el agente puede intentar nuevamente la llamada o pasar la conversación para un humano.

  • "stop" significa que el modelo escribió su respuesta final y el ciclo puede volver content al usuario.
  • "tool_calls" significa que el modelo está pidiendo a su código ejecutar una función con nombre y adjuntar el resultado antes de volver a llamar.
  • "length" significa que el presupuesto de tokens se agotó antes de completar la respuesta.
  • "content_filter" significa que un clasificador de seguridad detuvo la salida.

En ReAct moderno, un router corto lee este campo. Si el modelo pidió una herramienta, el router ejecuta su función, adjunta el resultado y llama el modelo nuevamente. Si el modelo se detuvo, el router devuelve la respuesta.

Este diseño funciona porque el modelo no queda atado al plan inicial. Cuando una herramienta devuelve algo inesperado, el resultado entra en la siguiente ronda de razonamiento y el modelo puede reevaluar la situación.

Las piezas de un agente de LLM

Al ampliar el agente aparece la descomposición que Lilian Weng presentó en 2023 . Un gran modelo de lenguaje está en el centro. Alrededor de él están memoria , planificación , herramientas y las acciones que interactúan con el mundo.

El agente mínimo de este curso llena cada componente con la solución más simple que funciona:

  • Memoria es array messages[] .
  • Planificación es el router finish_reason .
  • Herramientas son las funciones que el entorno de ejecución expone.
  • Acción es la llamada a herramienta que el entorno de ejecución ejecuta.

Ninguno de estos componentes vive dentro del modelo. Ellos forman parte del entorno de ejecución construido en torno a una única llamada de texto para texto.

Los componentes son independientes. Puede sustituir el modelo, las herramientas o el router por separado. Mientras cada componente respete el contrato esperado, el resto del ciclo seguirá funcionando.

Esta independencia también importa para cómo lee el código de un agente que no escribió. Cualquiera que sea el marco que lo involucre, cualquier agente basado en LLM debe contener estas cuatro piezas; cuando algo falla, la causa suele estar en una de ellas:

  • el modelo retornando el finish_reason equivocado,
  • un mensaje ausente en el array,
  • el ejecutor de herramientas devuelve un valor inesperado,
  • o el router leyendo la señal de forma incorrecta.

La estructura de cuatro piezas proporciona una lista de verificación que se aplica independientemente de cómo se organiza el código circundante.

Degradación del contexto: por qué un ciclo más largo lee peor

Este problema se vuelve más probable a medida que crece el contexto. La degradación del contexto ocurre cuando contradicciones, observaciones obsoletas y convenciones deficientes se acumulan en el historial hasta perjudicar la siguiente decisión. El efecto también tiene un componente posicional: Liu et al. (2023) mostraron que los modelos pueden subutilizar informaciones enterradas en medio de un contexto largo. Cuanto más Una señal importante se aleja del turno actual, más fácil es para el ciclo ignorarlo o contradecirlo.

Las mitigaciones habituales mantienen cada decisión cerca de la evidencia que necesita:

  • Plane antes de que el ciclo acumule observaciones,
  • delegue subtareas para que cada subagente trabaje en un contexto corto,
  • o resuma turnos anteriores antes de que se conviertan en un pasivo.

Cada mitigación añade costes de latencia, fidelidad o complejidad y debe evaluarse según la tarea.

Referencias

  • Yao et al., ReAct: Synergizing Reasoning and Acting in Language Models (2022). El trabajo original sobre la alternancia entre razonamiento, acción y observación.
  • Wei et al., Chain-of-Thought Prompting (2022) . La mitad "razonamiento" del ReAct ; lo que el modelo está haciendo dentro de reasoning_content cuando delibera antes de actuar.
  • Lilian Weng, LLM Powered Autonomous Agents (2023). La figura anterior adapta su descomposición: un modelo de lenguaje como controlador central, rodeado por memoria, planificación y uso de herramientas.
  • Xu et al., ReWOO: Decoupling Reasoning from Observations (2023). Un contraste con ReAct: el modelo escribe el plan de antemano y un ejecutor separado lo completa sin consultar de nuevo al modelo entre etapas.
  • Schick et al., Toolformer (2023) . Recobido nuevamente en las referencias del 1c; revista aquí para el mecanismo subyacente que el ciclo del ReAct explora.
