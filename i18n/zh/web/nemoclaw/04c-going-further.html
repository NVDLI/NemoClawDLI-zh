进一步探索

至此，您已经从头构建了智能体循环，将其置于内核级沙箱中，并衡量了策略留下的影响范围。

实际部署会引入自身的数据和用户。现在，您需要选择部署位置、如何接入自己的知识，以及在基础能力稳固后应重点解决哪些开放问题。

部署您构建的成果

将练习迁移到实际运行时

浏览器内练习的规模以学习为目的，使用代理端点，且会话会在每次运行之间重置。要将相同的工作迁移到持久化部署，就需要选择运行时、推理提供商，以及长时间运行会话的运维模式。托管端点无需学习者自行管理 GPU；本地推理要求取决于所选的提供商和模型。

  • NemoClaw 当前的先决条件列出了通用 Linux、macOS、通过 WSL2 使用 Windows，以及 DGX Spark 的路径。基准配置从 4 个 vCPU 和 8 GB RAM 起步；GPU 为可选项。随着要求和接口不断演进，请查阅最新文档。
  • build.nvidia.com 为每个由 NVIDIA 托管的模型提供与 OpenAI 兼容的端点。本课程中的 Python 和 JS 示例可原样粘贴到此处；只需将 baseURL 从可启动环境的代理改为 https://integrate.api.nvidia.com/v1，并提供 NVIDIA API key。账号访问权限和配额遵循当前服务条款。
  • NemoClaw applications 是您所运行可启动环境的配套示例库。NVIDIA 的 DGX Spark 实战指南会带您端到端构建完整的 NemoClaw 智能体，包括每日新闻摘要、软件开发智能体、演示文稿审阅器和日历协商器；每个示例都采用模块 4 介绍的同一套策略配置。可以选择其中一个，作为模块 3 中所打包常驻智能体的完整参考 blueprint。
  • 当模型需要在本地或 VPC 中运行时，请使用 NIM 自托管。 NVIDIA Inference Microservices 将模型、分词器和与 OpenAI 兼容的 HTTP 服务器封装在同一容器中。模块 1 和模块 2 中的 persona、Tooled 和 ReAct 智能体无需修改，即可对接 NIM API 入口。
  • 值得比较的框架包括： LangGraph 适用于类型化状态机； deepagents npm 软件包可实现 2c 中的 planner、 VFS 和子智能体结构；此外还有 CrewAI 和 AutoGen，适用于基于角色的智能体群。比较各个框架时，应考察它明确呈现了哪些工作：状态、工具、检索、委派、持久化和运行时策略。
延续这一界面

浏览器制品是一种可迁移的智能体交互界面

每个课程页面既是一节课，也是一个小型应用。界面会呈现状态、控件、中间结果和审批点；JavaScript 负责本地编排。当受众可以使用浏览器，却没有预先配置好的开发环境时，这种组合非常适用。它既能以交互方式解释系统、驱动动态工作流，也能为基于已加载数据和获准服务的通用脚本提供聚焦的前端界面。

迁移界面契约，再适配环境。 HTML、CSS、JavaScript、可见状态和审批控件都易于迁移。身份验证、跨域访问、持久化、文件系统访问范围、后端工具和主机 UI 桥接则不然。请将这些依赖置于精简的适配器之后，使工作流能够迁移，同时避免假定每种主机都授予相同权限。

如今，智能体产品已直接提供这种形式。Anthropic 将 Cowork live artifacts 描述为持久化的 HTML 交互页面，可从已连接的应用和本地文件刷新。OpenAI 预览版的 Apps SDK 允许由 MCP 支持的应用同时定义其聊天行为和交互界面。静态页面、托管制品和聊天内应用采用不同的主机契约，但都能将同一工作流呈现为可检查的状态与受限操作。

添加新知识

接入数据

模块 2b 中的 Index 智能体使用的是页面内的小型语料库。生产部署需要完成更多工作并考虑更多因素，因此以下参考资料可能对您有所帮助。

  • NeMo Retriever 是模块 2b 中余弦相似度检索的生产级后续方案。稀疏关键词搜索和稠密向量搜索会并行运行并合并分数，重排序器会按相关性重新排列候选结果，而可配置的分块原语则让您能够控制文档在建立索引前的拆分方式。将其与由 NIM 提供的嵌入结合，即可构建完全本地部署的检索栈，使数据始终留在 VPC 内。
  • NVIDIA AI Blueprints 为常见的智能体结构提供参考实现：一个 RAG 聊天机器人、一个多模态 PDF 提取器，以及一个研究助手。每个 blueprint 都是面向特定领域的 Research 智能体 (2c) 配置，并且可以完整部署。它们既可作为起始模板，也可用于对您自己的架构进行合理性检验。
  • NeMo Data Curator 将如何干净地接入自有语料库视为一个独立项目。它能处理去重、语言过滤、PII 移除和精确匹配评分，适用于已无法靠手工完成的规模。检索质量会随数据质量不断累积，因此只需清理一次语料库，就能让智能体此后针对该语料库发出的每次查询持续受益。
  • NeMo Guardrails 可添加运行在模型之上的应用层可编程输入和输出过滤器、主题策略及事实核查。它能补充内核级隔离，但不能取而代之：这两层会捕获不同类别的故障，因此应当同时运行。
下一步的突破方向

生产实践的分化方向

生产项目通常会在以下某个领域深入发展：

  • 知识层。生产级检索：结构化分块、页面图像检索，以及在真实异构语料库上开展忠实度评测。NeMo Retriever 和 RAG AI Blueprints 正是这些能力真正落地的地方。
  • 基础层。线格式协议（MCP、Responses API、OTel GenAI 约定和 A2A），用于保持工具能力在不同提供商和框架之间的可移植性。
  • 智能体群动态与隔离。当 N 个智能体并行运行时会发生哪些变化：每个智能体都会重复发现相同的上下文（重复发现成本）；包含过多跳转的拓扑会失去连贯性；负责评判同伴输出的智能体可能会因社交语境而非内容本身改变结论。当提示词规则和防护机制不足以限制影响范围时，如何使用内核级隔离（Landlock、seccomp、网络命名空间）约束智能体群中的任一智能体。

请选择与当前项目反复遇到的问题最匹配的方向。 NVIDIA 开发者博客会持续追踪这些领域的最新参考成果。

您实际构建了什么

本课程围绕可替换模型构建了一套智能体框架

在这些模块中，模型从未改变。模块 1 中承担推理工作的那个冻结、无状态模型，也正是深度研究智能体、OpenClaw 角色和沙箱隔离 claw 所使用的模型。

您编写的其余所有内容都是智能体框架，也就是封装原始模型，使其能够持续自主工作的系统。每个模块都为它增加了一层能力。

  • 循环。模块 1 将一次聊天调用转化为智能体：在调用外加入循环，让模型调用工具、接收返回结果并继续运行，直至完成任务。这个循环就是执行层。OpenClaw 之类的运行时或 LangGraph 之类的框架会为您提供这一层，无需您自行实现。
  • 工作流。模块 2 限定了每个阶段能够看到的内容，以及结果如何在固定工作流、检索和研究分支之间传递。决定哪些内容应纳入上下文、哪些应排除在外，就是上下文工程；它对输出质量的影响至少不亚于任何单个提示词的措辞（Weng, 2023）。
  • 运行时。模块 3 将这些工作流迁移到 OpenClaw 中；在那里，网关会话、工作区文件、技能和计划任务都能在一次浏览器调用结束后继续保留。
  • 隔离。模块 4 增加了一个完全不读取提示词的层。 OpenShell 在系统调用边界执行规则，因此即使提示词注入成功，也仍然无法突破策略限制。

工程成果积累在这些层中，而非模型本身。更强的模型只需少量调整便可接入同一套智能体框架，因此升级模型时可以继续沿用这些层。

当智能体反复以同一种方式失败时，通常是因为您尚未构建某个层；在更底层强制执行检查，比再次修改提示词更能持久地解决问题。以下模式展示了这类工作在实践中的具体形式。

部署经验

部署这类智能体时应牢记的要点

  • 对智能体生产力的预测往往存在系统性偏差。 METR 针对资深开源开发者开展的随机试验发现，使用 coding 智能体会导致显著减速，尽管参与者原本预计效率会提高，并且事后也报告称自己的效率有所提高。预测与实测结果之间的差距才是需要牢记的发现。因此，在评估您所部署的任何智能体的价值时，都应将这一点纳入考量。

  • 默认选择是使用单个强大的智能体。当任务复杂度超过某个阈值后，单个强大的智能体会胜过多智能体系统（Chen et al., 2024）。继续增加 N，涌现行为造成的危害可能会超过您原本试图修复的故障模式。向拓扑中再添加一个智能体之前，请明确指出它要解决的具体故障模式。如果无法明确说明，增加复杂度就不太可能有所帮助。

  • 内核级隔离决定了提示词注入成功后仍有哪些防护有效。提示词规则和应用防护机制虽有帮助，但它们只能处理模型向其暴露的内容；看似有效的注入指令会直接通过这些防线。

    因此，任何能够操作真实 shell 或文件系统，或者能够访问网络的智能体，都需要在提示词之下另设一层防护。该层在系统调用边界执行规则，位置低于任何指令能够触及的层级。

  • 智能体的管理员 token 位于比沙箱更高的边界。内核沙箱限制了智能体能够对外部环境执行的操作，却无法约束掌握智能体 operator token 的人。该持有者完全位于这一边界之上，可以自由执行以下任何操作：

    • 读取角色设定
    • 植入 cron 任务
    • patch 模型及其工具
    • 向对话中注入一轮消息

    沙箱的坚固程度与该 token 的权限范围是两个相互独立的衡量指标。

    模块 4b 展示了 token 如何越过沙箱根本无法看到的检查点。应像对待 root 密码一样保护 operator.admin 凭据：严格保管并定期轮换。对于该智能体而言，这项凭据的权限范围甚至超过了沙箱内部的 root。
