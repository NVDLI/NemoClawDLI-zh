持续运行的智能体

模块 3b 会在您发送消息时运行智能体。OpenClaw 还可以通过技能、心跳、 cron 作业和子智能体开始工作。每条路径仍会进入同一个智能体循环和 OpenShell 沙箱；具体运行内容由会话、指令和触发器决定。您将安装一项技能，并观察一次由 cron 触发的写入操作。

触发器如何选择上下文和指令

本页中的每种机制都由以下三个参数描述：

  • 会话决定一次运行继承谁的上下文。
  • 指令是告诉智能体该做什么的 markdown 文件。
  • 触发器决定何时开始运行。

下表展示了课程所用的配置。可以使用同样的三个字段对其它触发器类型进行分类；OpenClaw 还提供了其它会话模式。

名称会话指令所在位置触发器
技能（下方运行） 复用调用方的会话 workspace/skills/<name>.md 当指令与用户请求匹配时，模型会在轮次进行期间选择该技能
心跳（仅介绍概念） 此处为主会话 HEARTBEAT.md 网关计时器，默认约 30 分钟
Cron （下方运行） 此处使用隔离会话；每次触发都会新建JSON 即用型 prompt 字段 cron 调度，精确到分钟
子智能体（仅介绍概念） 新建会话，父智能体持有句柄调用 delegate() 时传入的内联字符串父智能体在轮次进行期间决定
OpenClaw cron 可以将作业绑定到主会话、隔离会话、当前会话或命名会话。本课程使用隔离的 cron 运行，确保每次演示都从全新状态开始。您将在本页运行技能和 cron 作业。心跳和子智能体的 delegate() 调用仅作为表格条目在此介绍；本页没有单元会触发它们，因此不必等待。

第 1 步 · 添加技能

技能最初是放置在 skills/ 目录下的 markdown 文件，通常包含一段简短的 front matter 或标题块，供运行时决定何时将其呈现给智能体。智能体不会一次性加载所有指令；当下一轮请求与某项技能匹配时，它会渐进式加载该技能。您无需重启或重新部署智能体，也无需亲自修改系统提示词。

# skills/triage-incident.md 当用户询问生产事故或粘贴可能表明发生事故的日志行时，请按以下顺序操作： 1. 确认受影响的服务和时间范围。 2. 从 /sandbox/runbooks/. 打开该服务的运行手册。 3. 建议最小且可逆的缓解措施；不要自行执行。 4. 创建 Jira 工单前先询问用户。

下方组件会要求智能体安装上述技能，然后发起一次专门设计为与其匹配的聊天补全。匹配过程自动完成。智能体会将请求与工作区中每项技能的描述进行比较，因此无需在提示词中指明所需技能。请观察智能体如何在第二轮使用这项新技能。

与 Kickstart 使用同一个运行时。您正在操作的就是在 Kickstart 页面上连接的那个 OpenClaw 智能体。

第 2 步 · 检查正在运行的智能体

调度作业位于网关上，而不是某个 HTTP REST 路由之后。因此， Control UI 使用的同一个 WebSocket 连接，也是您通过 cron 方法 cron.list、cron.add 和 cron.remove 列出和管理这些作业的通道。cron 作业按照自身计时器触发，使持续运行的智能体无需人工介入即可执行操作。课程运行时会为本次演示创建隔离会话。如果连续性比隔离性更重要，OpenClaw 也可以将调度工作绑定到其它受支持的会话模式。

下方组件将带您完成 cron 作业的整个生命周期：

  1. 它会建立连接，并列出已安装的 cron 作业。
  2. 它会安装一个每分钟触发一次的演示作业，并向 MEMORY.md 追加一行内容。
  3. 它会等待约七十秒，让作业跨过分钟边界并自动运行。
  4. 下一个单元会从沙箱中读取 MEMORY.md 的末尾内容，让您看到无人操作时由 cron 触发的智能体所写入的那一行。
  5. 最后一个单元会移除该作业，避免留下任何内容。

这次写入并非由人工提示触发，而是由 cron 调度自动驱动。即使您不在场，它也能代表智能体完成实际工作。

Cron 作业会在无人值守的情况下运行。如果某条调度指令要求智能体“发送每日报告”，无论您是否正在查看，它都会按时触发。课程会为每次触发选择一个隔离会话，因此某次运行中的错误不会污染下一次运行的记录。其它 cron 配置则可以在多次触发之间保留或绑定会话上下文。模块 4a 会在此基础上添加内核级隔离层。由 cron 触发的智能体尝试进行的每次文件系统访问和网络连接，都必须在系统调用执行前通过明确的允许列表检查。这样，即使调度作业行为异常，也只能访问策略允许的资源。

后续应用方向

公开的 Hermes 代码库提供了相同的几类广泛能力：可复用技能、持久化记忆、计划任务和消息网关。其实现方式和默认设置与 OpenClaw 不同，因此应比较两者的安全边界和会话行为，而不能因为功能名称相同，就认定风险控制措施也相同。

任何能够写入可复用指令、计划任务并接收远程消息的执行框架，都可能让受入侵指令在一次对话结束后继续存在。模块 4 会区分这些应用层控制与沙箱控制；后者用于限制文件系统、进程和网络访问。

Hermes 会限制其消息入口。Hermes 的最新安全指南介绍了配对码，以及平台级或全局用户允许列表；没有匹配的允许规则时采用 default: deny。这些应用层控制决定谁可以与智能体通信。操作系统沙箱则另行限制其工具能够访问的资源。

这种将技能作为记忆化轨迹的模式，在整个生态系统中还以其它名称和形式出现：

  • Wang et al., Voyager (2023)。这一理念的研究起源，通过 Minecraft 智能体得到演示。
  • LangGraph Persistence。利用带检查点的图实现保存和恢复。
  • Anthropic, Agent Skills。面向生产环境的技能文件夹布局。

动手实践 · 在对话中触发技能

通过网关与正在运行的智能体对话。如果您已在步骤 1 中安装 triage-incident 技能，请粘贴一段事故信息，观察智能体如何在对话过程中自行选用该技能，无需您说出技能名称。

心跳或 cron 触发时使用的也是同一套机制，只不过这次由您发送的消息驱动，而不是由计时器驱动。
