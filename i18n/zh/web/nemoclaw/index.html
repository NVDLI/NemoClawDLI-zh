课程主页

使用 OpenShell 和 NemoClaw 构建安全智能体

摘要

现代智能体无处不在，其概念并不复杂：将模型连接到工具和记忆，再通过路由决策持续运行，直至完成任务。本课程将从零开始构建这样的系统，随后把这些理念与软件工程师和非技术用户都在使用的现代框架联系起来。您将从一次 API 调用起步，逐步学习智能体协作、有依据的检索、深度规划，以及如何使用 NVIDIA OpenClaw 和 NemoClaw™ 进行安全部署。

1在下方确认模型路由。聊天和嵌入路由默认使用 build.nvidia.com。当服务容量受限时，请使用演示者提供的 Brev 聊天 API 入口完成一次设置；独立的嵌入路由保持不变。只有使用默认聊天 API 入口时才启用 iframe 模式。
2按照默认路径依次学习各模块，也可以直接跳转到您需要完成的任务。每个页面最后都会提供一个可直接运行的交互页面，其 JavaScript 代码也可供查看和修改。
3对于模块 3 至 4 中的智能体技术栈，请在课程提示时创建 NemoClaw launchable。它按照 NemoClaw Blueprint 的定义，在 OpenShell 中托管 OpenClaw 技术栈。课程服务栈在 CPU 上运行并使用托管模型 API 入口，因此这些练习不要求学习者自行管理 GPU。

学习目标

完成本课程后，学员将能够：

  • 构建基本的智能体循环，并识别其核心组件。
  • 在智能体系统中实现可靠的工具使用和函数调用。
  • 使用结构化路由模式设计和协调多智能体系统。
  • 开发自动化评估工作流，以衡量智能体的性能和可靠性。
  • 使用 OpenShell 配置智能体身份，并确保智能体在沙箱中安全运行。
  • 部署和管理自主智能体，同时构建持久化技能库。

输入 API Key

浏览器会将聊天和嵌入路由保存在 localStorage 中，因此一次设置即可应用于所有课程页面和标签页。浏览器只会将保存的密钥发送到其对应的 API 入口。只有演示者提供自定义聊天 API 入口时，才应在此处进行设置。Brev 聊天路由需要通过公共 HTTPS 隧道开放 5000 端口；私有隧道无法接收来自课程页面的跨源请求。课程页面既无法访问 Jupyter /lab URL，也无法访问 localhost:5000。托管 CORS 中继仅用于默认 API 入口下的 LMS/静态 iframe 模式。

智能体技术栈
Brev 上的 NemoClaw launchable
这是本次研讨会使用的沙箱化智能体技术栈。OpenClaw 用作智能体运行框架，OpenShell 提供 sandbox，NemoClaw 则是将二者组织成参考部署的 Blueprint。默认情况下，此技术栈部署在 Brev launchable 上；您也可以在本地部署，并相应修改代码。
