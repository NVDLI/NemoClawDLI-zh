浏览器文件的构建方式

本课程需要使用少量 LangChain API，但官方发布的文件会按名称引用其它软件包，其中一些还采用 Node.js 模块格式。静态浏览器无法自行解析这种依赖结构。

课程确定所需功能

一个小型入口文件会导入练习所需的五个 API。

锁文件确定软件包版本

npm 锁文件固定每个软件包的版本和 registry 完整性值，包括间接依赖项。

esbuild 跟踪导入关系

esbuild 会解析可达的 npm 依赖图，并将其合并为一个浏览器 ESM 文件。本项目不会压缩该文件。

为什么此处会出现 p-timeout

@langchain/core 和 langsmith 依赖 p-queue，后者依赖 p-timeout，而后者又依赖 p-finally。即使文件中没有特殊的法律声明，下表也会记录完整的依赖链。

保留的注释并非软件包清单

部分源代码作者会使用 /*! 或 @license 等形式标记注释。由于构建过程采用 esbuild 的 legalComments: "external" 设置，esbuild 会将这些已标记的注释移至 .LEGAL.txt。普通依赖项可能没有此类注释，而内嵌的复制代码即使带有注释，也不一定是独立的 npm 软件包。

课程包含的 npm 软件包

“本项目直接选用”表示课程明确请求了该软件包；“由……引入”表示某个已包含的软件包将这项间接依赖带入了浏览器文件。每个许可证链接都会打开随当前课程版本提供的完整许可证文本。

可复现范围

确切的 npm 输入记录在 scripts/browser-vendor/package.json 和 package-lock.json 中。内嵌源代码的依据固定到官方 @langchain/core@1.1.48 标签和 commit。CI 会重新生成浏览器文件，拒绝无法映射的法律声明部分，验证每项许可证和哈希，并检查依赖图是否与 CycloneDX 清单一致。学习者运行时代码中不允许使用软件包 CDN URL。
