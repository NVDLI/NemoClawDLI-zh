模块 3 · 第 1/3 部分 · 开始实时调用

连接 NemoClaw 技术栈

模块 1 和模块 2 中，编排一直在浏览器内进行。一旦页面不再承载消息、中间结果或分支状态，工作流便会结束。模块 3 将相同的智能体模式迁移到受 OpenShell 保护的 NemoClaw/OpenClaw 运行时。该运行时既可以是通过 http://localhost:8011 等浏览器端代理开放的本地 non-Brev 部署，也可以是公开课程使用的托管 Brev launchable。OpenClaw 会保留会话历史记录和基于文件的工作区，同时继续提供工具；OpenShell 则限制正在运行的智能体能够访问的范围。您将在浏览器中比较无状态模型 API 和持久化 OpenClaw 网关。

下图从左到右展示了这一演进过程：

  • HTTP REST API 入口。模型会独立处理每次调用：使用 Chat Completions API 时，历史记录由代码携带；使用 Responses API 时，则由服务器保存。
  • Model Context Protocol。这是一种标准通信协议，使运行时无需为每个工具编写专用连接代码即可访问工具。
  • 持久化网关。OpenClaw 会保持 /cli/gateway WebSocket 连接，并通过 JSON-RPC 流式返回事件，而不是逐个请求进行响应。

接下来将使用的两个 API 入口

模型 API 入口仍使用前面介绍的 API。运行时网关连接到能够保留会话并运行工具的 OpenClaw 进程。支持这些协议的代码仍可在单元格中查看，但需要重点关注的是 API 入口、凭据和状态边界。

NemoClaw/OpenClaw 运行时

本地环境可以在 OpenShell 中运行 OpenClaw，并通过本地代理公开 Control UI，例如 http://localhost:8011。身份、工具、会话记忆和 sandbox 策略都位于该运行时中，而不在课程页面内。浏览器通过 /cli/gateway 上的 WebSocket 网关访问智能体。托管课程也可以改用 NemoClaw Brev launchable；其 App URL 可能使用 Cloudflare Access 或 Pomerium，下方的连接下拉列表支持这两种方式。

网关 token 身份验证。会话通过 x-openclaw-session-key 标识。

步骤 1 · 探测 API 入口

下方组件会向每个 API 入口发送一个小型请求并显示返回内容。绿色表示已就绪。

模型路由设置

模型探测只读显示课程主页或模块 1a 中配置的持久化聊天路由。在此修改一次后，基准测试和后续课程都会复用该路由。下方的 NemoClaw/OpenClaw 运行时设置与其相互独立。

不同模型的延迟和首 token 时间

选择模型前应先进行测量。下方单元格会从目录中筛选匹配的模型，向每个模型流式发送一个简短提示词，并记录各模型的首 token 时间 (TTFT) 和完成时间。获取目录的单元格默认展开，以便在运行基准测试前查看筛选列表。

如果 OpenClaw 探测超时或返回 502。智能体运行框架可能尚未启动完成。这通常是因为 OpenClaw 还未完成策略 YAML 加载，运行时便已启动。请等待 30 秒，然后点击“再次探测”。如果服务仍未恢复，请先使用下方网关部分中的 Recover 单元，再继续操作。

可编辑代码：探测请求

公开的代码会发出与探测工具相同的请求，并复用探测工具保存的 URL、token、访问提供商和会话。编辑 PATH、METHOD 和 BODY 即可发送其它请求。状态、标头和响应正文会显示在下方。

TRANSPORT 控制凭据如何到达运行时：

  • "configured" 使用已保存的路由。本地代理 URL 通常保持直接连接；跨源 Brev Cloudflare URL 默认使用 NVIDIA 中继。
  • "direct" 使用 credentials: "include" 调用已保存的运行时源，并依赖部署所使用的匹配浏览器 Cookie。

本地代理部署通常只需要网关 token。Pomerium launchable 将其签名会话保存在浏览器中。课程直接使用其 WebSocket，并通过经过身份验证的终端中的固定环回请求读取两个引导 API 入口。Cloudflare Access launchable 使用托管中继和显式会话字段。当课程内置于同一个 NemoClaw 运行时中时，直接模式属于同源访问，无需使用中继。

步骤 2 · 网关

模型 API 入口使用 Chat Completions API，一次 POST 即可携带调用所需的全部内容。

  • 请求行是发往 completions 路由的一次 POST。
  • JSON 请求正文包含 model 和 messages。
  • Authorization 标头用于标识调用方。

OpenClaw 内部也实现了同一路由，但单独托管的课程需要通过运行时访问层连接该路由，而不能从未经身份验证的浏览器请求直接访问。本地部署可以通过本地代理路由访问；Brev 部署则可能增加 Cloudflare Access、Pomerium 或托管中继。

向您开放的通道使用另一种协议：/cli/gateway 上通过 JSON-RPC 通信的 WebSocket。

浏览器标签页中的 Control UI 并未使用特殊的私有通道。它通过同一个 /cli/gateway WebSocket 与智能体通信，而您也可以访问该通道；它需要的唯一凭据是网关 token。上方探测使用的正是该网关 token。较旧的 launchable 可通过 GET /api/agent 的 agent.dashboardUrl 公开此 token。当前本地 OpenClaw 部署通常会改为输出包含 #token=... 的 dashboard URL；请让 Base URL 继续指向浏览器端代理，并将该 token 粘贴到探测工具中。

该 token 具有 operator.admin 作用域，与 Control UI 拥有相同的权限。借助它，可以：

  • models.list 会列出运行时提供的所有模型。
  • cron.add 会调度无需您在场即可运行的任务。
  • 带有 chat.send 的 sessionKey 会将消息直接送入正在运行的智能体循环。

更改运行时设置前先检查

受支持的 NemoClaw/OpenClaw 部署通常会报告 tools.toolSearch=false。自定义配置仍可启用该选项，因此运行状况检查会先读取实时值，之后 Recover 才会进行任何更改：

  • 症状：您请求执行命令后没有收到任何返回，运行过程停滞，随后超时。
  • 原因：toolSearch 允许模型通过为桥接器编写代码（tool_search_code · “运行桥接代码”）来访问工具，导致模型在该桥接器上反复循环，而不调用 exec。
  • 恢复：运行运行状况检查。如果 toolSearch 已开启且 exec 探测失败，Recover 可以通过 config.patch 将其关闭。清除会话和重启仍需您主动选择。

运行时调整完成后，您便可以将消息送入智能体循环。下方三个单元会按顺序运行：前面的单元先建立连接并列出模型和定时任务，后续单元再发送一轮聊天，最后一个单元则以流式方式返回跟踪记录。请逐行阅读该记录：

  • 每个 ⚙️ 行都表示一次工具调用及其输入参数。
  • 每个 ✓/✗ 行都表示该工具的结果。
  • 网关不会转发模型的推理过程，因此该输入/输出跟踪记录是您能够查看到的最详细逐步信息。如果运行过程停滞且没有返回结果，请改用上方的 📜 日志单元持续查看运行时日志。

每次聊天运行都会自行检查：如果某次运行记录了 ⚠ DEGRADED，请返回此处运行 Recover，然后重试。

任何能够读取运行时环境的人都能读取该 token，而 token 的读取者就是拥有上述所有权限的 operator。模块 4 将把这一便利机制转化为核心安全问题。

步骤 3 · 记忆存储在会话密钥中

每次 chat.send 都接受一个 sessionKey，该密钥决定当前轮次能记住哪些内容：

  • 连续两次使用相同密钥：网关会在第二轮运行前恢复第一轮的历史记录，因此智能体可以根据客户端从未重新发送过的对话作答。
  • 使用不同密钥：全新开始，不继承任何内容。

下方第一个单元会先写入一个事实，然后使用相同的密钥要求智能体复述该事实。由于网关在服务器端恢复了历史记录，智能体可以根据客户端从未重新发送过的轮次作答。另外两个单元可供您管理已存储的状态。

  • Clear 只需一次调用即可清除一个会话，使下一轮从空白状态开始。每个聊天单元还包含一行已注释的 sessions.reset，可用于直接重新开始。
  • Clean up 会清除您在实验过程中积累在 Control UI 中的临时会话（包括步骤 2 中每次运行所用的密钥），仅保留 Main Session。
客户端只发送会话密钥来标识对话。每次调用前，网关都会根据这一个字符串在服务器端解析出完整会话，因此客户端无需自行发送对话记录。任何两个存在差异的密钥都会指向两个不同的会话，即使它们背后的对话内容完全相同。
