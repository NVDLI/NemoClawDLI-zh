现代 CLI 智能体

下文比较的智能体都封装了相同的几项能力：

  • 一个工作目录
  • 一组工具
  • 一套记忆
  • 可选的无人值守运行方式，例如 cron、长时间任务或队列作业
  • 网络访问

它们的安全特征取决于默认开放哪些能力，以及是否启用无人值守执行。底层运行时还必须能够拦截不当调用。

模块 4a 区分了应用层决策与操作系统层的强制执行。应用封装位于这条边界之上。在构建您自己的浏览器端 CLI 智能体之前，您将先比较这些封装。

相同的循环，不同的应用默认设置

每个产品都让模型在循环中使用工具，但默认设置和内置能力各不相同，实现细节也有差异。这些因素带来的成本与便利性共同构成下文所说的框架负担。

  • Claude Code (Anthropic)。项目根目录使用 CLAUDE.md 作为指引文件，另有 ~/.claude/CLAUDE.md 用于用户级通用规则。它提供丰富的工具集（编辑、bash、Web、子智能体、长时间任务），并可通过钩子拦截工具调用；默认设置较为保守：您需要主动授权，才能扩大文件和网络访问范围。
  • Codex CLI (OpenAI)。指引文件为 AGENTS.md。其默认沙箱采用审批模式：每次写入或执行 shell 命令都需等待确认，除非您传入 --full-auto。它的工具集以 shell 为核心，连文件编辑也通过 shell 完成。
  • Cursor（驻留于 IDE）。指引文件为 .cursor/rules/*.mdc。智能体与编辑器集成，因此工具集围绕编辑器操作设计（“将此差异应用到文件 X”），其沙箱权限取决于编辑器和 OS 已授予的权限。
  • Hermes (Nous Research)。这是一个可自我改进的终端智能体：它会从经验中创建技能，跨会话保留记忆，运行内置 cron，并可通过网关从 Telegram、Discord 和 Slack 访问。它的应用形态与 OpenClaw 相同，并启用了自我修改和消息交互接口。
  • OpenClaw（位于 NVIDIA NemoClaw 中）。这就是您一直在操作的智能体。它以整个 workspace/ 文件夹作为指引（SOUL.md、AGENTS.md、 IDENTITY.md 及其它文件）。它支持通过网关管理的触发器进行无人值守运行；在 NemoClaw 参考栈中，它运行于 OpenShell 沙箱内部，因此无论模型如何决策，其工具集都受内核策略约束。

请注意，Hermes 似乎不同于编辑器 CLI，因为它默认支持“自动学习”，并将其作为旗舰功能。不过，该系统使用的底层组件仍与其它智能体相同（具备写入权限的技能、cron 和记忆更新），因此这种风险并非 Hermes 独有。

OpenShell 可以承载这类智能体应用；NemoClaw 是本课程使用的参考栈。NVIDIA 还记录了 Codex、Cursor 和 OpenCode 的相同 OpenShell 集成方式。您选择的 CLI 决定初始默认设置，而它外层的 OpenShell 封装则控制这些默认设置获准触达的范围。

自由度就是攻击面

所有这些智能体都沿着相同的维度进行配置，每个维度都代表一种可以授予或限制的能力。下表中的 NemoClaw 列直接取自可启动环境正在运行的 OpenShell 策略，也就是您在模块 4a 中实时读取并验证过的策略。

自由度控制项NemoClaw 默认设置（实时策略）
文件系统哪些路径可读或可写 仅可写入 /tmp、/sandbox/.openclaw、/sandbox/.nemoclaw 和工作目录；系统路径只读。由 Landlock (best_effort) 强制执行。
网络出站访问按二进制文件分别限定主机、端口及 HTTP 方法/路径 默认拒绝；仅设置一个简短的允许列表（NVIDIA 推理、inference.local、clawhub/npm），每一项都限定为一种 HTTP 形式，并绑定到特定二进制文件。
进程身份智能体以哪个用户身份运行 以非 root 用户 sandbox 运行；seccomp 会阻止 ptrace、mount 和 setuid。

动手试试 · 在不同智能体框架间权衡同一项任务

该页面从以下维度比较不同智能体框架的复杂程度：

  • 智能体框架隐藏的抽象：您需要编写的代码更少，但对实际运行过程的了解也更少。
  • 其中内置的假设和默认设置：它们决定了在您提出要求前，智能体框架会介入到什么程度。
  • 开箱即用的一等功能：与之对照的是需要您自行实现的同等能力。

描述一项任务，比较每种智能体框架提供了多少现成机制。可编辑单元会公开其系统提示词和响应逻辑，并展示示例。编辑后重新运行该单元即可重新构建交互页面。

构建一个以此浏览器为 shell 的 CLI 智能体

上述 CLI 将智能体 attach 到真实计算机的终端。您也可以用浏览器自身的 JavaScript 运行时作为 shell，构建相同的结构。下方智能体只有一个工具 js，它通过该工具编写 JavaScript，并在当前实时页面中运行。智能体读取返回结果后，再决定下一步运行什么。运行时已加载，因此无需搭建任何额外的智能体框架。它的触达范围仍然很广：智能体可以读取 DOM、调用 fetch 并使用课程辅助函数，所有操作均在您正在阅读的标签页内完成。

模块 4c 将回到这种浏览器形态，并将可迁移部分—具有可见状态和控件的交互式 Web 界面—与特定宿主提供的身份验证、存储、网络和工具适配器区分开来。

在 launchable 上打开真实 shell

NemoClaw launchable 通过模块 4a 策略探测所使用的同一条 /ws/terminal 连接，为您提供真实的宿主 shell。该宿主提供 openshell CLI，即用于管理沙箱化智能体的 operator 工具。您在下方输入的每一行都会在 launchable 上运行，输出也由它直接返回。

请先在模块 3a 中连接 launchable。输入命令、点击快捷项，或按 Tab 键自动补全。在宿主上，openshell sandbox list 会显示智能体，openshell status 会报告网关状态。智能体在沙箱内运行，因此可在命令前加上 agent，让命令在其中运行：agent ls 会通过 openshell sandbox exec 列出智能体的文件。每条命令都在各自的短生命周期 shell 中运行，因此如需与智能体进行交互式对话，请使用下方面板，而不是 openclaw tui。

与智能体对话

openclaw tui 是一种交互式全屏对话界面，单次运行的终端无法让它持续保持打开。下方面板通过 OpenClaw 网关与同一个实时智能体通信，使用的是 /cli/gateway 连接，模块 3b 和模块 3c 也使用这条连接，因此您无需离开当前页面即可与智能体对话。面板会流式显示智能体的回复，并展示智能体运行的每项工具或命令。请先在模块 3a 中连接 launchable（及其 URL 和 token）。可以提出任何问题、点击提示词，或按 Tab 键自动补全。

上方终端属于 operator 平面。在 launchable 的宿主 shell 中，openshell 负责管理沙箱化智能体，因此宿主是位于策略之上的控制平面，也就是模块 4a 指出的边界。您通过 agent <cmd> 推送给智能体的命令会在其默认拒绝策略下运行，而宿主 shell 则受 operator 管理。

  • 搭建成本。 launchable 已为您预配并在运行。在您自己的计算机上，CLI 首次运行前需要完成安装并配置运行时。
  • 触达范围。在智能体内部，内核策略会限制每次调用，也就是您在模块 4a 中了解的默认拒绝规则。在您自己的计算机上，CLI 可以读写文件，并访问整个网络。
  • 影响范围。智能体内部的提示词注入只会影响该沙箱，并留下审计记录。同样的注入若发生在您自己的计算机上，则会作用于真实文件。页面开头关于自由度的论述，现在已成为您手中的实际选择。

只要任务需要持久化和标签页无法承载的实际工作，更重的智能体框架就物有所值。真正值得培养的能力，是准确判断任务需要多重的框架；模块 4c 将以分层视角总结这一点。
