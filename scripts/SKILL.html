scripts/ bundle toolchain

The script tree is hierarchical. Implementations live in named subdirectories; the root holds only the directory beacon, bootstrap helper, and placeholder. Use runtime for the link engine, validation for gates, skills for SKILL contracts, build for packaging, compliance for source governance, materials for vendored references, figures for runtime diagram checks, edx for export helper pages, dev for local operator helpers, security for iframe proxy and dependency vulnerability audits, git-hooks for local hooks, and translate for language branches.

For course-cell helper examples, open web/nemoclaw/scripts/SKILL.html. It now reads like a runnable notebook: local examples run without services, while model and OpenClaw examples explain the key or podman deployment needed before they call live helpers.

Run commands from the repository root. Use grouped paths directly; new root-level scripts are rejected by the hierarchy guard. For Studio, runnable cells, or browser-page changes, run scripts/runtime/browser_env_probe.sh before deciding browser smoke is unavailable. OpenClaw fallback is gated by python3 scripts/validation/openclaw_fallback_audit.py.
